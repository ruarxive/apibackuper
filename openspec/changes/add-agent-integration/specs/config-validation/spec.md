## ADDED Requirements

### Requirement: Machine-readable validation
`apibackuper validate-config --json` SHALL print a JSON object with `valid`,
and lists of `errors` and `warnings`, where each entry has the configuration
`path`, a `message` and, when known, a `hint`. Exit statuses SHALL match the
text mode.

#### Scenario: Wrong type reported with path
- **WHEN** `params.page_size_limit` is the string `"100"`
- **THEN** the JSON output has an error with `path` `params.page_size_limit`
  and the exit status is 1

### Requirement: Missing pagination parameter warning
`apibackuper validate-config` SHALL report a warning when `project.iterate_by`
is `page`, `skip`, `range` or `cursor` and the parameter that mode needs
(`page_number_param`, `count_skip_param`, `count_from_param` with
`count_to_param`, or `cursor_param`) is not configured, because such a run
saves only the first page.

#### Scenario: Config generated by detect without page parameter
- **WHEN** a configuration has `data.total_number_key` but no `params.page_number_param`
- **THEN** `validate-config` reports a warning for `params.page_number_param`
  and `validate-config --strict` exits with status 1

### Requirement: Schema export
`apibackuper schema` SHALL print the bundled configuration JSON Schema to stdout.

#### Scenario: Agent reads the schema
- **WHEN** a user runs `apibackuper schema`
- **THEN** stdout is the JSON Schema used by `validate-config`
